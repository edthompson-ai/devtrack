Reading the results

Indexes pay off for selective lookups and anti-joins: the full trace for one requirement, finding commits with no task, full-text search. Whole-table aggregations (cycle time, review turnaround) read every row anyway; Postgres keeps its hash joins and doesn't change, while SQLite, which has no hash join, can switch to slower nested loops through a new index. Every index also costs write time and disk, so each one in 002_indexes.sql is tied to a query it serves.
